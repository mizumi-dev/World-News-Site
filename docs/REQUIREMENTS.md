# 要件定義書 — 全世界ニュースまとめサイト（プロトタイプ）

このドキュメントは、実装を担当するAI（または開発者）が追加の質問なしで作業に着手できることを目的とした要件定義である。技術的な設計は `docs/SPEC.md`、作業手順とタスク分割は `docs/IMPLEMENTATION_PLAN.md` を参照すること。

## 1. コンセプト

- ユーザーが「見たい国」を複数指定すると、各国の主要ニュースメディアの新着ニュースが一覧できる個人用ニュースまとめサイト。
- ニュースは自動で収集され、**AIによって日本語の短い要約（1〜2文）**が付与されて表示される。
- 既存の類似アプリ（例:「世界の新聞 - 200の国」）は機械翻訳止まりであり、本アプリは **AIによる要約・文脈補足** で差別化する。

## 2. MVPスコープ

### やること

| # | 要件 | 詳細 |
|---|------|------|
| R1 | 対応国 | 8カ国に固定: 日本(jp)・米国(us)・英国(gb)・ドイツ(de)・インド(in)・ブラジル(br)・ケニア(ke)・韓国(kr)。先進国と途上国を混在させる意図がある。国の追加が設定ファイル1箇所の編集で済む構造にする |
| R2 | 国選択 | ユーザーは表示したい国を複数選択できる（タブまたはドロップダウン + チェックの複数選択UI）。選択状態はブラウザの `localStorage` に保存する（アカウント機能は作らない） |
| R3 | ニュース取得 | 外部ニュースAPI（NewsData.io を第一候補、World News API を代替。SPEC参照）から国別の新着ヘッドラインを取得する |
| R4 | AI要約 | 取得した各記事に対し、Qwen API（Alibaba Cloud、コスト最優先で `qwen-turbo` を採用）で **日本語1〜2文の要約** を生成する。原文が日本語以外の場合は翻訳を兼ねる。可能なら「なぜこのニュースが重要か」の文脈を一言補足する |
| R5 | 表示項目 | 各記事カードには **見出し（日本語化したもの）／AI要約／メディア名／発行時刻／原文リンク** のみ表示する。**記事本文は取得しても表示・保存しない**（著作権への配慮） |
| R6 | レイアウト切替 | 「新聞風」と「まとめ風（2chまとめサイト風のカジュアルなリスト）」の2レイアウトをトグルボタンで切り替えられる |
| R7 | 新聞風の紙面割り | 新聞風レイアウトでは、選択した国数に応じて紙面のセクション（トップ／準トップ／その他）への国の割当が自動で決まる（アルゴリズムは SPEC 5.2）。各セクションのヘッダから担当国を手動で差し替えることもできる |
| R8 | 手動リフレッシュ | 画面上の「更新」ボタンでニュースの再取得・再要約を行う。自動更新は行わないが、将来 cron 化できる構造にする（取得〜要約のパイプラインをHTTP経由で叩けるAPIルートとして実装する） |
| R9 | キャッシュ | 取得・要約結果はサーバー側にキャッシュし、リフレッシュ以外ではAPIを叩かない（無料枠・APIコスト保護。SPEC 4.4） |
| R10 | レスポンシブ | スマートフォンでも読みやすいこと。新聞風はモバイルでは1カラムに崩れてよい |
| R11 | 環境変数 | APIキーはすべて環境変数で渡す。`.env.example` をリポジトリに含める |
| R12 | README | APIキーの取得方法・ローカル起動手順・拡張ポイント（国の増やし方、cron化の方法）を記載する |

### やらないこと（非対象）

- 全世界200カ国対応（将来拡張。構造だけ対応しておく）
- ユーザーアカウント・認証・課金・パーソナライズ設定のサーバー保存
- 収益化・広告
- 記事本文の全文表示・転載
- 自動定期更新（cron）の実装そのもの（構造の準備のみ）

## 3. 受け入れ条件（MVP完了の定義)

1. `npm install && npm run dev` と `.env` の設定だけでローカル起動できる。
2. 国を1つ以上選んで「更新」を押すと、選択国の新着ニュースが日本語見出し＋日本語要約付きで表示される。
3. 8カ国すべてで取得〜要約〜表示が動作する。
4. レイアウトトグルで新聞風／まとめ風が切り替わり、選択が localStorage に記憶される。
5. スマートフォン幅（375px）で崩れず読める。
6. ニュースAPI・Qwen APIのキーが無い/不正な場合、画面にわかりやすいエラーメッセージが出る（クラッシュしない）。
7. README の手順どおりに第三者がセットアップできる。

## 4. 品質・運用上の注意

- **コスト**: 要約はキャッシュ必須。同一記事を二度要約しない。1回のリフレッシュで要約する記事数に上限を設ける（国ごとに最大10件、SPECのenv `MAX_ARTICLES_PER_COUNTRY` で調整可能）。
- **著作権**: 表示は見出し・要約・出典・リンクのみ。要約は原文の複製にならない長さ（1〜2文）に制限する。
- **障害耐性**: 一部の国の取得や一部記事の要約が失敗しても、成功した分は表示する（全滅させない）。
- **秘匿情報**: APIキーをクライアントに露出させない。ニュース取得・要約はすべてサーバーサイド（Next.js Route Handler）で行う。
